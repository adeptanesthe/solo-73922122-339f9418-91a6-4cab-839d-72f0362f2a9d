# 再生塑料配方试配筛选（质检模型 + 最优改配求解 + 合格概率归因）

面向再生塑料配方研究员的网页工具：录入原配方与各原料的上下限、锁定项后，
在**合格概率 ≥ 0.7** 的约束下，按 **先最少改变原料种数、再最小化总克数改变量**
的字典序求出最优试配方案；只有求解器**证明**无解才报无解，求解失败单独报告。

## 技术栈与模型

- **FastAPI** 提供网页与 JSON API；**scikit-learn** 训练随机森林；**z3-solver** 求解。
- 质检模型：`RandomForestClassifier(n_estimators=5, max_depth=3, random_state=20241117)`，
  在固定种子生成的合成数据上训练（Dirichlet 采样的配方比例 + 含噪质检规则，阈值取中位数
  使类别均衡）。每次启动以同一种子重训，结果确定（自测第 1 项验证同种子重训一致）。
- 配方为 4 种原料的整数克数，总重 1000 克；模型输入为克数 ÷ 1000 的 **float32** 比例。

## 求解语义（与分类器严格一致）

- sklearn 树内部以 float32 特征与 float64 阈值比较。求解器把每个分裂条件
  `float32(g/1000) <= τ` 预计算为等价的**整数截断** `g <= K`（`app/model.py: cutoff_left`），
  因此 z3 中的约束与原分类器的实际阈值语义逐点一致（自测第 2 项对全部阈值 × 0–1000 克逐点核对）。
- 森林概率 = 5 片叶子概率（精确有理数）之和 / 5 ≥ 0.7，以精确有理数编码进 z3。
- 字典序优化用**两阶段**实现：先最小化改动种数，固定该最优值后再最小化总改动克数。
- 每份建议解出后**用原 sklearn 分类器复算概率**（float32 输入），未通过复核则按求解失败上报，
  绝不当作合格建议展示。
- 结果状态严格区分：`ok`（已证明最优）/ `infeasible`（z3 判定 unsat，即证明无解）/
  `invalid`（输入不合法）/ `solver_failure`（z3 unknown、超时或异常，**不**当作无解）。

## 合格概率归因（新增页面 `/attribution`）

试配员调整原料用量后，质检工程师需按**原模型**解释合格概率的变化，先复核贡献最大的原料。

- **输入**：调整前后两份 4 料整数配方，各自总重必须为 1000 克（非负；否则不出报告）。
- **中间配方（4 料共 16 份子集）**：对子集 S 固定其中各原料的**调整后**用量，其余原料按
  **调整前配方比例**补齐到 1000 克（`app/attribution.py: fill_intermediate`）：
  - 参考剩余量 > 0：按 `剩余量 × 原克数 / 参考合计` 取精确有理数，先下取整，
    余克按「小数余量从大到小、余量相同则下标从小到大」的固定规则分给参考量 > 0 的原料
    （最大余数法；参考量为 0 的原料恒得 0 克）；
  - 参考剩余量全为零：把剩余量均分给其余原料，不能整除的余克按下标从小到大逐一 +1。
  - 两种分支都保证每份中间配方为**非负整数且总重恰为 1000 克**；固定项为空集/全集时
    分别恰为调整前/调整后配方。
- **推理**：用**原随机森林**（同一固定种子模型）对每份中间配方的 float32 比例调用
  `predict_proba`，与试配的概率复核走完全相同的路径。
- **贡献**：按标准 Shapley 组合权重 `s!(n-s-1)!/n!` 对 16 份子集值加权，得到 4 料**有符号**
  贡献 φ_i；页面展示调整前/后两端概率、实际概率差、逐原料贡献（含用量变化）、贡献和，
  以及**误差 = 贡献和 − 实际概率差**（理想情况为 0，页面以浮点原值展示）。
- **优先复核**：取 |φ_i| 最大者为“建议优先复核”的原料（并列时取下标靠前者）。
- **撤回**：与试配页相同的 epoch + AbortController 机制——任何配方编辑都会立即撤下旧报告
  并中止在途请求；迟到的旧响应即使成功返回也按序号丢弃，**不恢复**报告。
- 非法输入（总重≠1000、负数、单项>1000、长度≠4、非整数/布尔、缺字段）一律返回 `invalid`，
  **不携带任何报告字段**，页面也只显示“输入不合法”。计算异常单独返回 `internal_error`
  （不冒充非法输入）。

## 运行

### Docker Compose（推荐）

```bash
docker compose up --build
# 打开 http://localhost:8000
```

### 本地开发

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

## 页面与交互

- 录入：4 种原料的原配方克数、各自下限/上限、锁定勾选；总重须为 1000 克。
- 「载入可行样例」「载入无解样例」：样例在服务启动时由真实模型 + 求解器**实测验证**后生成
  （`app/samples.py`），可行样例含锁定项，无解样例为上下限把配方逼入不合格区域的情形。
- **计算期间可随时修改**：任何输入修改会立即撤下旧建议（清空结果区）、中止在途请求；
  迟到的旧响应按请求序号（epoch）比对后直接丢弃，不会恢复显示（`app/static/index.html`）。
- 结果展示：合格概率（原分类器复算值）、逐原料改动明细、改动种数与总克数、最优性结论、求解耗时。
- 顶部导航可进入**归因页** `/attribution`（见上节）；归因页也可返回本页（`/`）。

## API

| 端点 | 说明 |
| --- | --- |
| `GET /` | 单页网页（配方试配） |
| `GET /attribution` | 归因网页 |
| `GET /api/meta` | 模型规格（树数、深度、种子、阈值、特征名） |
| `GET /api/samples` | 经求解器实测的可行 / 无解样例 |
| `POST /api/solve` | 求解；体：`{original, lower, upper, locked}`（各 4 元） |
| `GET /api/attribution/sample` | 归因页示例（调整前 / 调整后两份配方） |
| `POST /api/attribution` | Shapley 归因；体：`{original, adjusted}`（各 4 元整数克数） |

## 完成说明（据实）

**已实现**

- 原试配功能全部保留：合成数据 + 固定种子随机森林（5 棵树、深度 ≤ 3）；z3 按原分类器真实阈值
  语义编码；两阶段字典序最优求解；每份建议用原分类器复算；四种结果状态严格区分；
  可行/无解样例（启动时实测）；计算期可修改、修改即撤回、迟到结果不恢复；Docker Compose 交付。
- 归因网页 `/attribution` 与 `/api/attribution`：两份 1000 克整数配方录入；16 份按固定规则
  补齐的中间配方（比例补齐 + 最大余数、参考全零均分 + 余克固定分配）；原随机森林 float32
  推理；4 料有符号 Shapley 贡献；两端概率、实际概率差、贡献和与误差、优先复核项、
  中间配方明细；非法输入不出报告；编辑即撤下旧报告、迟到响应不恢复；试配页与归因页互相导航。
- 页面兼容性：归因页在报告渲染前还会校验服务端返回的每个贡献/中间配方字段，任何残缺、
  NaN/字符串数值或越界下标都不会被渲染成报告（作为防御性措施，不替代服务端校验）。
